# 04 — 第一条真实只读 SQL 问答

**What to build:** 让用户提出一个简单中文经营问题后，由确定性 Fake LLM 通过原生工具调用契约执行一条真实 PostgreSQL 聚合查询，并在同一条 SSE 流中看到工具状态、结果表格和中文答案。这个切片建立 CommerceTrace 自主实现的 LLM、工具与查询边界。

**Blocked by:** 02 — 匿名身份与持久化对话; 03 — 固定种子的中文电商数据基线.

**Status:** ready-for-agent

- [ ] LLM 请求、响应、流式增量和工具调用使用稳定的类型契约，工具参数由 Pydantic 模型生成并校验。
- [ ] Tool Registry 只注册显式允许的工具，未知工具和无效参数返回结构化失败而不会执行。
- [ ] 确定性 Fake LLM 能按预设脚本先请求 `run_sql`，观察工具结果，再生成最终中文答案。
- [ ] `run_sql` 在测试配置下只接受受控的简单读取查询，并使用不能写入业务数据的数据库角色。
- [ ] 成功结果包含列、行数、有限预览、执行时间和稳定结果哈希；空结果被表示为成功但零行。
- [ ] 前端按顺序展示工具开始、工具完成、结果表格和最终答案。
- [ ] 主端到端测试从中文问题经过完整 SSE 流断言真实数据库结果，不依赖私有类或调用顺序。
- [ ] 真实外部模型在完整 SQL 安全切片完成前不作为可启用运行模式。
