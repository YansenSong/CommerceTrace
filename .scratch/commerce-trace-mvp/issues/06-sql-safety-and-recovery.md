# 06 — SQL 双层只读安全与错误修正

**What to build:** 让用户和模型只能对电商业务数据执行有界的 PostgreSQL 只读查询，并在查询可修正地失败时获得脱敏反馈。应用层和数据库层必须相互独立地阻止写入、越权、危险函数和敏感值探索。

**Blocked by:** 04 — 第一条真实只读 SQL 问答.

**Status:** ready-for-agent

- [ ] PostgreSQL 方言 AST 校验只允许单条 `SELECT`、`WITH ... SELECT` 和受控 `EXPLAIN`，拒绝 DDL、DML、多语句和配置的危险函数。
- [ ] 查询只能访问允许的业务 Schema 与必要元数据，无法读取应用身份、对话、Evidence 或记忆数据。
- [ ] 数据库角色、只读事务和语句超时在绕过应用校验的集成测试中仍能阻止写入或限制失控查询。
- [ ] 普通查询最多返回 500 行；低基数 `SELECT DISTINCT` 探索只允许配置的非敏感列并最多返回 50 个候选值。
- [ ] 客户姓名、地址、联系方式及其他敏感列不能用于值级探索。
- [ ] 数据库错误映射为安全错误码、脱敏消息和可重试标记，连接信息、凭据与原始技术错误不会进入模型或 SSE。
- [ ] Fake LLM 场景证明可重试错误能触发修正查询，空结果仍按成功观察处理。
- [ ] 安全合同测试覆盖允许查询、所有拒绝类别、结果限制和应用层与数据库层的独立防线。
