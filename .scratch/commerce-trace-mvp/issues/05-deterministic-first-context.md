# 05 — 首轮确定性 Schema 与业务上下文

**What to build:** 让 Data Agent 在第一次模型调用前稳定获得整个小型电商数据库的压缩 Schema 与关键业务口径，使表、字段、关系和指标理解不依赖模型主动记得检索。

**Blocked by:** 04 — 第一条真实只读 SQL 问答.

**Status:** ready-for-agent

- [ ] 完整 Schema 从 PostgreSQL 元数据生成，覆盖全部业务表、字段类型、主外键关系、中文含义和必要固定枚举。
- [ ] 上下文包含可比较的 Schema 版本与指纹，且相同结构产生相同指纹。
- [ ] 版本化业务规则和指标定义可以被加载，并保持中文业务说明与英文数据库标识符的对应关系。
- [ ] Context Assembler 在第一次 LLM 调用前确定性组装完整 Schema、相关业务规则和指标，不把 Schema 放入向量检索。
- [ ] SSE 发出不泄露完整 Prompt 的上下文检索完成事件，前端显示核心上下文已准备。
- [ ] 契约测试检查上下文包含所需语义、版本和指纹，不对 Prompt 全文做脆弱字符串快照。
- [ ] 当上下文装配失败时，请求以安全错误结束，不会在缺少核心 Schema 的情况下继续生成 SQL。
