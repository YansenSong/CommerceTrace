# 07 — 受预算约束的单 Agent 状态机

**What to build:** 让用户的问题由一个显式、可观察且有预算上限的单 Agent 完成理解、必要澄清、计划、工具执行、观察、自我修正和综合。真实 OpenAI-compatible 客户端与确定性 Fake LLM 应遵守同一契约。

**Blocked by:** 05 — 首轮确定性 Schema 与业务上下文; 06 — SQL 双层只读安全与错误修正.

**Status:** ready-for-agent

- [ ] Agent 请求状态显式记录会话与请求、问题、计划、当前步骤、上下文、工具轮数、业务 SQL 次数、按目的重试次数、Evidence、生成组件和终态。
- [ ] 简单问题生成一个可展示步骤，归因类问题最多生成五个步骤；不向用户暴露模型隐藏思维。
- [ ] 只有销售额、退款、时间范围或比较基准的实质歧义会触发澄清，澄清后本次请求安全终止并等待用户回答。
- [ ] Agent 只能通过 `run_sql`、`visualize_data` 和 `search_memory` 的原生 Tool Calling 契约行动。
- [ ] 单一 OpenAI-compatible 客户端正确往返 assistant tool calls 与对应 tool messages，并使用异步接口避免阻塞服务事件循环。
- [ ] 每个请求最多十轮工具调用、五次业务 SQL，同一分析目的最多修正两次 SQL。
- [ ] 达到任一预算上限时返回已有结果、未完成步骤和明确停止原因，而不是把请求标记为普通成功。
- [ ] SSE 和前端能够展示计划创建、步骤开始、工具状态和预算终止；Fake LLM 状态机测试覆盖所有允许终态。
- [ ] 真实模型测试需显式标记并从普通快速测试中排除。
