# 08 — Evidence 约束的可追踪答案

**What to build:** 让用户得到的每个定量结论都可以追溯到真实执行过的 SQL 与结果，并能在界面展开核验。系统必须在最终答案完成前验证引用，而不是只依赖 Prompt 要求模型自觉遵守。

**Blocked by:** 07 — 受预算约束的单 Agent 状态机.

**Status:** ready-for-agent

- [ ] 每次被分析采用的成功 SQL 可以形成 Evidence，并关联分析步骤、工具调用、主张、SQL、列、行数、结果哈希和执行时间。
- [ ] Evidence 与对应工具轨迹持久化到当前用户的会话和请求下，可从存储精确回放。
- [ ] 最终答案中的定量主张以稳定 Evidence 标识引用至少一条已执行查询。
- [ ] 后端在发出答案完成事件前验证所有定量引用存在、属于本次请求且指向成功结果。
- [ ] 引用不存在、跨请求、指向失败查询或缺失定量引用时，系统不会把答案标记为成功完成。
- [ ] 前端 Evidence 卡片默认展示主张摘要，并允许展开 SQL、结果预览、执行时间和结果哈希。
- [ ] 完整 Prompt、连接信息、原始数据库错误和模型隐藏思维不会作为 Evidence 保存或展示。
- [ ] 主端到端测试同时断言 SSE 中的引用关系和 PostgreSQL 中可观察的 Evidence 副作用。
