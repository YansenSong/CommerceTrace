# 03 — 固定种子的中文电商数据基线

**What to build:** 让项目评审者可以从空数据库生成一套可复现、业务关系一致的中文电商数据，并明确知道数据集已经准备就绪。数据应包含支持简单经营分析与后续多步归因所需的完整业务模型和受控异常。

**Blocked by:** 01 — 可流式运行的 CommerceTrace Walking Skeleton.

**Status:** ready-for-agent

- [ ] 数据库包含客户、品类、商品、订单、订单明细、支付、退款和每日库存快照，并建立正确的主外键关系。
- [ ] 生成过程由固定种子和版本化场景配置驱动，仓库不保存完整生成数据文件。
- [ ] 数据中通过调整上游分布植入华东订单量下降、数码退款率上升、信息流新客低复购和库存不足导致取消增加四类场景，而不是事后修改聚合结果。
- [ ] 自动验证订单金额可由明细重算，支付、退款、订单状态和库存关系满足既定业务约束。
- [ ] 每个植入场景达到配置的最小效果，且相同种子与配置生成相同的数据结果哈希。
- [ ] 标准启动或初始化状态能够明确报告数据版本、种子、结果哈希和是否就绪。
- [ ] 支持较小的快速测试数据规模与默认演示规模，两者使用相同业务规则。
