# 11 — Evidence 门控的 Candidate 自动积累

**What to build:** 让系统在不打扰用户的情况下积累真正被最终答案采用的成功 SQL，但始终把这些经验视为未经验证的 Candidate。后续语义相近的问题可以受限参考它们，却不能把历史结果当成事实。

**Blocked by:** 08 — Evidence 约束的可追踪答案; 10 — 可完全重建的 Trusted 业务记忆.

**Status:** ready-for-agent

- [ ] Candidate 由后端在答案引用确定后登记，不向 LLM 暴露保存记忆工具。
- [ ] 只有执行成功且被最终 Evidence 引用的 `run_sql` 调用可进入 Candidate；失败查询、未引用探索和可视化调用不会登记。
- [ ] 记录包含问题、分析步骤、规范化 SQL、涉及表列、Schema 指纹、指标版本、执行时间、行数、列名、有限摘要和结果哈希。
- [ ] 规范化与唯一约束阻止等价经验重复累积，同时保留最近验证时间。
- [ ] 不保存完整结果、模型隐藏思维、失败轨迹或临时探索文本。
- [ ] 每次最多召回两条 Candidate，排序始终低于适用的 Trusted，并在模型上下文中明确标记为未验证历史经验。
- [ ] Candidate 只有在 Schema 指纹和指标版本仍适用时才可召回；其中的 SQL 每次重新安全校验和真实执行。
- [ ] 端到端测试证明第一次问题登记 Candidate，措辞不同的第二次问题能够检索它，但不会复用第一次结果。
