# 13 — 销售额下降的有限多步归因

**What to build:** 让中文电商经营人员询问“销售额为什么下降”时，系统可以围绕植入场景执行有限的描述性归因，展示分析计划、多个真实查询、Evidence 与图表，并以审慎措辞总结主要相关因素。

**Blocked by:** 09 — 绑定真实查询结果的受控图表; 10 — 可完全重建的 Trusted 业务记忆.

**Status:** ready-for-agent

- [ ] Agent 为归因问题生成不超过五个可展示步骤，并根据已获得 Evidence 更新步骤状态。
- [ ] 分析能够覆盖总体变化、订单量与客单价拆分、地区和品类贡献，以及取消、退款或库存影响中的相关路径。
- [ ] 整个问题仍遵守最多五次业务 SQL、十轮工具调用和同目的两次修正预算。
- [ ] 每个最终因素及贡献数字引用对应 Evidence，且图表字段来自这些真实结果。
- [ ] 最终答案先给结论，再给证据、图表与口径说明，并使用“主要相关因素”“贡献”或“数据表明”等描述性措辞。
- [ ] 系统不会宣称完成严格因果推断、预测或未由植入场景和查询证据支持的结论。
- [ ] 确定性 Fake LLM 端到端场景能够识别至少一个植入异常，并正确处理其中一个反证或空结果步骤。
- [ ] 预算不足时返回已完成因素、未完成步骤和停止原因，而不编造完整归因。
