# 以分析证据判定任务完成

自由文本回答无法证明每条结论由哪次数据操作支持，也无法准确表达复杂分析只完成了一部分。我们决定让每个分析步骤声明步骤完成条件，受控查询执行后产生可追溯到查询工件的结构化分析证据；步骤与任务只有在实际证据满足完成条件时才标记完成，否则必须返回部分完成或失败及其未满足条件。最终回答从已取得的证据生成并保留引用关系，而不是把查询轨迹作为与结论无关的附件。

- **Status**: accepted
- **Considered Options**:
  - 自由文本回答附带 SQL 轨迹：改动最少，但不能验证结论与查询之间的对应关系。
  - 对每个自然语言句子做细粒度引用：追溯最强，但生成和展示成本过高，也容易制造脆弱的文本位置关系。
  - **步骤完成条件 + 实际证据（选定）**：以分析步骤为粒度定义数据需求，再用执行后取得的事实判定完成并支撑结论。
- **Consequences**: 后端响应和持久化需要表达步骤完成条件、步骤状态、实际证据引用与未满足条件；最终回答可以总结多个证据，但不得把未取得的事实写成结论。
