# 单 Agent 决策与确定性分析工作流并存

DataAgent 需要让模型处理开放式分析判断，又必须保证 Schema 获取、查询计划、SQL 校验、执行、结果核验和呈现等关键步骤不能被跳过。我们决定保留单 Agent 负责分析决策，由后端显式工作流维护分析任务状态并强制阶段门；所有问题共用同一种分析任务模型，简单问题形成一个分析步骤，复杂问题形成带显式依赖的多步分析计划。现阶段不引入多 Agent，待出现跨数据源、Python 分析或稳定的专业角色分工后再评估。这样吸收 DB-GPT 的 Agent/Workflow 分治与 WrenAI 的 plan/validate/execute 分离，同时避免把任务可靠性继续寄托在提示词约定上。

- **Status**: accepted
- **Considered Options**:
  - 纯 ReAct Agent + 提示词约束：实现最简单，但现有 `get_schema → plan_query → run_sql` 顺序无法由后端保证。
  - 多 Agent 规划与角色协作：适合跨角色复杂任务，但当前单库经营分析场景不足以覆盖新增协调成本与失败面。
  - **单 Agent + 确定性分析工作流（选定）**：模型决定分析内容，后端强制关键阶段、状态转移和失败恢复。
- **Consequences**: 简单与复杂问题不维护两套 Agent 或两套工作流；分析计划必须把业务步骤与数据库的 SQL 执行计划明确区分。
- **User-visible progress**: DataAgent 在执行数据操作前先发布分点分析计划，随后逐项更新状态；同一时刻最多一个步骤处于进行中，完成步骤在状态栏中明确勾选或划去，失败步骤保留错误与未取得的证据。
- **Controlled revision**: 分析计划可以根据新证据修订，但只能变更尚未开始的步骤；已完成步骤及其证据保持不可变。每次修订都记录原因并推送给用户，同时受最大步骤数、最大修订次数和运行预算约束。
