# 分析运行独立于 HTTP 请求持久存在

复杂分析会包含多次模型调用和查询，无法可靠地限制在一次同步 HTTP 请求内；客户端断开也不应导致计划、查询工件和失败位置丢失。我们决定把每次执行建模为持久化的分析运行，消息入口创建运行，客户端通过事件流观察计划、步骤、查询和最终结果，并能在重连后读取当前状态或重试失败步骤。第一阶段运行仍可由 FastAPI 进程内执行，只有部署到多实例或需要跨进程恢复时才引入队列适配器。

- **Status**: accepted
- **Considered Options**:
  - 同步请求内完成：接口简单，但超时、断线、进度反馈和步骤恢复都不可靠。
  - 立即引入外部任务队列：恢复和横向扩展能力最强，但当前本地单实例部署会承担不必要的运维成本。
  - **持久化运行 + 进程内执行 + 事件流（选定）**：先建立稳定运行语义和接口，并为未来队列适配保留接缝。
- **Consequences**: 对话消息与分析运行分别持久化；客户端不能再假设发送消息的响应就是最终答案；步骤执行需要幂等，并通过事件序号支持安全重连。事件流必须覆盖计划发布、步骤开始、步骤完成、步骤失败和最终状态，使前端状态栏能够实时重建且刷新后保持一致。
