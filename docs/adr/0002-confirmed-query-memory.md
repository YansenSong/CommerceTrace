# 确认后记忆（Confirmed-Query Memory）

当前每轮对话都让 LLM 从零生成 SQL，重复问题没有复用。我们决定：用户显式确认（或纠正）后的问答才沉淀为可复用的 few-shot 记忆。Markdown 是真相源，按确定性 slug 存在 `knowledge/sql/*.md` 并由 Git 跟踪（可评审、可回滚）；向量库只做派生的可丢弃索引，语义检索作为后续升级项。

- **Status**: accepted
- **Considered Options**:
  - SQL 执行成功即自动入记忆：零前端改动，但会记住"能跑但错"的查询，污染后续 few-shot（参考项目明确警告"记住成功 SQL 不自动等于正确"）。
  - 混合状态机（未确认/已确认/已纠正）：两全但多一条状态机复杂度。
  - **用户显式确认（选定）**：质量基准线由业务确认保证；代价是少量前端改动（确认/纠正入口）。
- **Consequences**: 记忆质量依赖用户确认习惯，未确认的问答不沉淀；需要在前端暴露"确认/纠正"入口，并提供按问题相似度（token overlap）取 top-N 注入提示词的检索逻辑。标记同步一致性由调用方保证。
