# 用业务语义模型支撑渐进披露

表结构、查询权限和指标公式目前分别硬编码在 Schema 目录、安全策略和 Prompt 中，容易漂移，而且指标公式不能被后端确定性展开或校验。我们决定建立轻量、版本化的业务语义模型，统一定义业务对象与物理表映射、关系、指标、维度、同义词和治理标签；紧凑目录、字段上下文、SQL 安全策略和提示词均从该模型派生。上下文仍采用渐进披露，第一阶段只对高价值指标提供确定性 SQL 展开，不实现 WrenAI 完整的 SQL 编译器。

- **Status**: accepted
- **Considered Options**:
  - 继续维护多个硬编码事实源：短期改动少，但 Schema、权限和指标会产生不可检测的漂移。
  - 直接引入完整语义 SQL 编译器：能力最完整，但当前 SQLite 单库场景不足以覆盖实现与迁移成本。
  - **轻量业务语义模型（选定）**：先统一事实源并确定性实现核心指标，保留未来扩展成语义编译器的路径。
- **Consequences**: ADR-0001 被本决策替代；渐进披露策略继续保留，但其内容从业务语义模型派生。业务语义模型需要版本、校验器和变更后的回归评测，不能退化为另一份只供模型阅读的配置文件。
