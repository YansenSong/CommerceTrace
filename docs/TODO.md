## 后端 Agent 能力

### 真正的多轮对话上下文

- 当前实现只持久化和回放会话消息；每次请求仍只把当前用户问题发送给模型，能力边界应暂时定义为“有会话记录的单轮 Agent”。
- 为 `ConversationLedger` 增加按用户和会话读取历史消息的接口，并在读取时强制校验会话所有权。
- 在 `prepare_execution()` 前组装当前轮所需的历史用户消息和助手消息，保持消息时间顺序及角色语义正确。
- 设计明确的上下文窗口和 Token 预算策略，避免无上限加载整个会话；需要确定保留最近轮次、历史摘要和关键事实的优先级。
- 明确历史工具调用、工具结果、Evidence 和 Chart 是否进入模型上下文，以及哪些内容只能用于界面回放、不能被新一轮直接信任。
- 如果允许复用历史 Evidence，需要校验用户、会话、数据版本、Schema 版本和查询结果有效期，防止跨会话或过期证据污染结论。
- 支持“继续分析”“刚才那个地区”“换成净销售额”等依赖前文的指代、省略和口径修正。
- 增加多轮测试，覆盖正常承接、历史裁剪、口径覆盖、跨用户隔离、无效会话、超长会话和历史工具消息配对。
- 实现前修正产品与架构文档中关于“多轮对话”的表述；实现后再将其恢复为正式能力声明。

### 通用歧义识别与澄清

- 不再通过问题文本白名单逐条拦截特定问法。
- 设计结构化的歧义判定结果，至少覆盖指标口径、时间范围、比较基准、筛选维度和归因目标。
- 只有缺失信息会实质改变查询或结论时才请求澄清；可以使用安全默认值时，应明确告知采用的口径。
- 重新引入澄清状态前，先定义稳定的事件/API 契约，避免把某一种业务问题写进 Agent 主流程。
- 增加同义改写、否定表达、多歧义组合和无需澄清场景的评测用例。

### 通用时间范围与数据覆盖校验

- 使用结构化时间范围，而不是匹配“上个月”等固定词语。
- 统一解析绝对日期、相对时间、季度、同比、环比和自定义区间。
- 从数据源或 Schema 元数据获得各事实表的真实覆盖范围，不依赖 SQL 返回列名约定。
- 在执行查询前后统一校验目标时间与数据覆盖范围。
- 明确区分“业务值为 0”“查询无记录”“目标时间超出覆盖范围”和“数据源不可用”。
- 生成结论时引用覆盖范围证据，但不针对某个指标或某种时间表达硬编码文案。

### 工具失败的确定性控制策略

- 当前 `ToolFailure.retryable` 只会被序列化到工具消息中，Agent Core 不会根据它决定继续、重试或终止；真实模型是否遵守该提示不可控。
- 不可重试的 SQL 失败目前也会进入下一轮模型调用，并被计入 SQL 重试次数，最终可能被错误归因为 `sql_retry_limit`。
- 重新定义失败策略，避免只用一个布尔值表达所有情况；至少区分“允许模型修正后重试”“当前工具调用不可重试但可继续分析”“必须终止当前请求”。
- 重新审查错误分类：SQL 语法、字段和参数错误通常可修正；越权 Schema、危险函数及明确的安全拒绝应采用确定性阻断策略。
- Agent Core 必须直接消费结构化失败策略，不能把控制权完全交给模型。
- 只有实际允许重试的失败才能增加对应重试计数；保留原始停止原因，避免被通用预算原因覆盖。
- 明确 `enable_sql_retries=False` 对各类失败的行为，避免同时阻断本可修正的错误。
- 增加测试，覆盖可修正重试成功、不可重试不再调用工具、安全错误终止、预算计数和最终停止原因。
